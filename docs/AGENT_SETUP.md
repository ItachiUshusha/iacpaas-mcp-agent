# Запуск агента в VS Code и Python

Подготовлены два интерфейса к одному MCP API: custom agent в VS Code и отдельное Python-приложение. Python-агент получает схемы через `tools/list`, отправляет их модели, исполняет выбранные ею вызовы через `tools/call` и передаёт результаты обратно модели до ответа или уточняющего вопроса.

## Начать с VS Code

1. [Установите окружение](../README.md#быстрый-запуск-на-windows) и откройте корень репозитория через **File → Open Folder** в локальном окне VS Code.
2. Откройте встроенный Chat, выберите **Copilot** в списке окружений сеанса и войдите под своей учётной записью GitHub. Выберите доступную модель с поддержкой вызова инструментов.
3. Во встроенном терминале PowerShell выполните:

```powershell
.\run.ps1 serve --transport http --mode live --login --fund-login
```

Введите логин и пароль IACPaaS в терминале и оставьте сервер работающим. Флаг `--fund-login` включает чтение «Моего Фонда» и перенос папок в корзину.

4. `.mcp.json` подключает сервер `iacpaas` по адресу `http://127.0.0.1:8765/mcp`. В палитре команд откройте **Chat: Open Customizations → MCP Servers** и выберите `iacpaas`. Для старого режима **Local** тот же адрес указан в `.vscode/mcp.json`.
5. В списке агентов выберите **IACPaaS** из `.github/agents/iacpaas.agent.md`. Для создания личных папок и их переноса в корзину оставьте ручные разрешения (**Manual permissions** в Copilot) и подтверждайте вызов после проверки пути. В отдельных клиентах действуют их собственные настройки подтверждения.

Сервер слушает только loopback и работает под одной учётной записью IACPaaS. После завершения остановите его Ctrl+C. Если сервер не отображается, проверьте папку открытого проекта, выбранный сеанс и включение `iacpaas` в настройках. Для отказа подключения откройте **Show Output** в меню сервера и проверьте, что терминал MCP всё ещё работает. Если фонд возвращает `FUND_LOGIN_REQUIRED`, проверьте запуск с обоими флагами. [Руководство VS Code по MCP](https://code.visualstudio.com/docs/agents/run/manage-mcp-servers).

### Примеры запросов к агенту

| Запрос | Что раскрыть в журнале инструментов |
| --- | --- |
| Найди «Базу свойств материалов» и прочитай её корень. Укажи путь и источник. | Поиск ресурса и `get_inforesource` для найденного пути. |
| Прочитай подграф «Базы свойств материалов» на глубину 1. Посчитай вершины и связи в этом фрагменте. | `get_subgraph` и `count_graph` с глубиной 1. |
| Какие общие примеси указаны у газов на основе водорода и аргона? Покажи исходные записи обоих классов. | `analyze_gas_composition`, компоненты и исходные вершины из двух классов. |

Для этих запросов нужны права на соответствующие ресурсы. Подтверждение операции с папкой описано [отдельно](FOLDERS_AND_DETERMINISM.md).

### Альтернативный stdio для IDE

Чтобы проверить IDE без входа, в режиме **Local** скопируйте содержимое `config/mcp-stdio-snapshot.json` в `.vscode/mcp.json`. Сервер будет запускаться IDE автоматически и читать только сохранённый корень.

Для live-stdio предусмотрен `config/mcp-stdio-live.json`: он запрашивает **API-ключ IACPaaS, выдаваемый администратором**, через защищённую input-переменную VS Code. Обычный пароль аккаунта сюда не подходит. Если у вас только логин и пароль, используйте готовый HTTP-вариант. Секретов в поставляемых JSON-файлах нет.

## Отдельное Python-приложение

Выберите провайдера с поддержкой вызова инструментов.

| Вариант | Что нужно | Как вызывается модель |
| --- | --- | --- |
| OpenAI | API-ключ и точный ID доступной модели с function calling | Responses API на `api.openai.com`; графовые результаты отправляются выбранной модели |
| Ollama | Установленный Ollama, запущенный локальный сервис и скачанная модель с tool calling | Локальный `/api/chat` на `127.0.0.1:11434`; облачный ключ не используется |
| Совместимый API | Ключ провайдера и точный ID доступной модели с tool calling | Chat Completions, запуск с `--provider compatible` и при необходимости `--base-url` |

В примерах `MODEL_ID` — место для точного ID вашей модели, не готовое имя. Приложение намеренно не выбирает произвольную модель вместо пользователя. У Ollama имена установленных моделей показывает `ollama list`; не все модели поддерживают инструменты.

OpenAI, чтение живого графа:

```powershell
.\run.ps1 agent --provider openai --model MODEL_ID --mode live
```

Ключ берётся из `OPENAI_API_KEY`; если переменной нет, приложение предлагает скрытый ввод в обычном терминале. Затем выполняется отдельный вход IACPaaS. Ключи и пароль не нужно писать в чат или в исходный код.

Ollama, чтение живого графа:

```powershell
.\run.ps1 agent --provider ollama --model MODEL_ID --mode live
```

Без `--mode live` используется сохранённый корень. Для проверки HTTP-транспорта добавьте `--transport http`: приложение само запустит и остановит локальный MCP-сервер на свободном порту.

Чтобы Python и VS Code использовали **один уже работающий сервер**:

```powershell
.\run.ps1 agent --provider openai --model MODEL_ID --mcp-url http://127.0.0.1:8765/mcp
```

С Ollama замените `--provider openai` на `--provider ollama`. При `--mcp-url` режим данных и учётные данные определяются уже работающим сервером; локальный `--mode` не переключает его. Повторный вход IACPaaS не нужен.

По умолчанию запускается диалог. Пользователь отвечает на уточнения следующим сообщением, история сохраняется в памяти. `/exit` завершает работу. Для одного вопроса:

```powershell
.\run.ps1 agent --provider openai --model MODEL_ID --mode live --question 'Найди систему единиц физических величин и назови разделы непосредственно под корнем.'
```

В режиме одного вопроса ответ может оказаться уточняющим вопросом модели. Это нормальная остановка диалога, а не подтверждение выполнения исходной задачи; для продолжения используйте интерактивный режим.

## Архитектура

```text
VS Code custom agent ───────────┐
                               ├─ MCP stdio / Streamable HTTP
Python CLI → model tool calls ──┘      → server.py → domain.py
                                           → iacpaas_client.py → IACPaaS
```

- `agent.py` — CLI, вход, подключение к MCP и диалог.
- `agent_core.py` — ограниченный агентный цикл, проверка аргументов/результатов, политика и трасса.
- `providers.py` — адаптеры OpenAI Responses, Ollama и совместимого Chat Completions. В общем цикле инструменты выбирает модель. Для отдельных точных запросов о фонде и сравнении двух классов газов используется фиксированная последовательность вызовов MCP.
- `agent_instructions.md` — правила и границы ответов Python-агента.
- `.github/agents/iacpaas.agent.md` — роль и список разрешённых инструментов агента IDE.
- `server.py`, `domain.py`, `iacpaas_client.py` — MCP-сервер, единый доменный слой и HTTP-клиент IACPaaS.

Вместо LangChain/LangGraph реализован небольшой собственный runtime function calling: диалог → запрос модели → список вызовов → проверка схем/политики → MCP → результаты модели → ответ/следующий вызов/уточнение. Он покрывает соответствующий цикл задания, но не предоставляет визуальный редактор графов исполнения LangGraph.

## Ограничения и диагностика

Python-агент сверяет доступные инструменты с разрешённым списком и проверяет аннотации чтения и записи. Путь ресурса подтверждается вызовом каталога или фонда. Аргументы и структурированные результаты проверяются по JSON Schema. Диагностируемые ошибки передаются модели, чтобы она могла скорректировать запрос.

Пределы одного пользовательского запроса: 8 шагов модели, 16 вызовов инструментов, до 8000 символов вопроса. Контекст модели — до 1 МБ, ответ HTTP от модели — до 2 МБ, ожидание модели — до 180 секунд. При достижении лимита приложение сообщает об остановке, не выдавая её за успешный ответ.

Чтение и подсчёт ограничены глубиной 0..3, 200 описаниями вершин и 128 КБ выдачи. Для поиска внутри ресурсов есть отдельные ограничения. Счётчики описывают возвращённый фрагмент. Для чтения найденной записи Python-агент использует `read_export_node` с указателем и хешем экспорта. [Источники ответов и пределы поиска](GROUNDED_ANSWERS.md).

Запись ограничена созданием папок и переносом папок в корзину. Python-агент сверяет точный путь с прямой командой из текущего сообщения. MCP при переносе проверяет совпадение `path` и `confirm_path`, защищённые пути и тип выбранного объекта. Успех подтверждается ответом IACPaaS. [Политика операций с папками](FOLDERS_AND_DETERMINISM.md).

Трассы Python сохраняются в `data/traces/agent-*.jsonl`: вопросы, имена/аргументы/результаты вызовов, конечные ответы и статус запуска. Заголовки, пароль, полный ответ авторизации и скрытые рассуждения модели туда не записываются; известные процессу секреты маскируются. Трасса может содержать данные графа и пользовательский текст. Папка исключена из архива и Git.

Для OpenAI `store=false`; история, включая возвращённые API элементы продолжения рассуждений, остаётся в памяти процесса и передаётся следующему запросу для корректного продолжения tool calling. Секрет модели не передаётся процессу MCP. Ответы графа считаются данными, а не инструкциями; ограничения инструментов дополнительно обеспечиваются кодом.

## Проверки и установка

После клонирования репозитория установите окружение и выполните проверки:

```powershell
.\setup.ps1
.\run.ps1 doctor
.\run.ps1 test
.\run.ps1 smoke
```

`doctor` проверяет наличие компонентов и локального Ollama. Доступ аккаунта и вызовы инструментов выбранной моделью проверяются отдельно. `test` запускает серверные, агентные и провайдерные тесты. В сценариях с подменённой моделью проверяются известные ответы и ошибки. Проверка обоих транспортов охватывает поиск, чтение, обработку неверной глубины и подсчёт.

`smoke` проверяет вызовы MCP без подключения модели.
