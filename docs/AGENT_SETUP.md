# Этап 3 — ИИ-агент для IACPaaS

Подготовлены два интерфейса к одному MCP API: custom agent в VS Code и отдельное Python-приложение. Python-агент получает схемы через `tools/list`, отправляет их модели, исполняет выбранные ею вызовы через `tools/call` и передаёт результаты обратно модели до ответа или уточняющего вопроса.

**Состояние на 18 октября 2026 года:** код и локальные проверки готовы. Прошли 23 теста, включая настоящий MCP stdio/HTTP с подменённой моделью. Реальный запуск с LLM и три демонстрации в VS Code ещё не выполнены. Их нельзя заменить тестами с подменёнными ответами. Этап пока не отмечен полностью завершённым.

## Начать с VS Code

1. Откройте **корневую папку репозитория `iacpaas-mcp-agent`** через File → Open Folder. Тогда `${workspaceFolder}` указывает на этот проект.
2. Откройте встроенный Chat, проверьте вход и доступную модель с поддержкой инструментов. Установка Codex сама по себе не подтверждает доступ к модели в этом чате. Если нужно, выполните предложенный VS Code вход в GitHub/Copilot.
3. Во встроенном терминале PowerShell выполните:

```powershell
.\run.ps1 serve --transport http --mode live --login
```

Войдите в IACPaaS в терминале. Оставьте сервер работающим. Вход в браузере для него не используется.

4. Конфигурация `.vscode/mcp.json` уже указывает на `http://127.0.0.1:8765/mcp` под именем `iacpaas`. В палитре команд выберите `MCP: List Servers`, затем `iacpaas`; проверьте подключение и наличие четырёх инструментов. Ошибки доступны через `Show Output`. Если VS Code запросит доверие к папке, это стандартная настройка IDE для запуска конфигурации этого проекта.
5. В выборе агента встроенного Chat выберите **IACPaaS** из `.github/agents/iacpaas.agent.md`. Если используется другой agent harness, проверьте, что он читает workspace-конфигурацию VS Code; для этой инструкции нужен локальный режим встроенного Chat.
6. Выполните три сценария из `DEMO_SCENARIOS.md`, сохраняя фактические ответы и видимые вызовы инструментов. Обычный ответ модели без нужных MCP-вызовов не считается доказательством сценария.

HTTP выбран по умолчанию, чтобы входить обычным логином и паролем в терминале, без копирования JWT в настройки IDE. Сервер слушает только loopback и работает под одной учётной записью IACPaaS. После завершения остановите его Ctrl+C.

### Альтернативный stdio для IDE

Чтобы проверить IDE без входа, скопируйте содержимое `config/mcp-stdio-snapshot.json` в `.vscode/mcp.json`. Сервер будет запускаться IDE автоматически и читать только сохранённый корень.

Для live-stdio предусмотрен `config/mcp-stdio-live.json`: он запрашивает **API-ключ IACPaaS, выдаваемый администратором**, через защищённую input-переменную VS Code. Обычный пароль аккаунта сюда не подходит. Если у вас только логин и пароль, используйте готовый HTTP-вариант. Секретов в поставляемых JSON-файлах нет.

## Отдельное Python-приложение

Доступны два варианта модели; ни один не был запущен с реальной LLM в ходе подготовки:

| Вариант | Что нужно | Как вызывается модель |
| --- | --- | --- |
| OpenAI | API-ключ и точный ID доступной модели с function calling | Responses API на `api.openai.com`; графовые результаты отправляются выбранной модели |
| Ollama | Установленный Ollama, запущенный локальный сервис и скачанная модель с tool calling | Локальный `/api/chat` на `127.0.0.1:11434`; облачный ключ не используется |

В примерах `MODEL_ID` — место для точного ID вашей модели, не готовое имя. Приложение намеренно не выбирает произвольную модель вместо пользователя. У Ollama имена установленных моделей показывает `ollama list`; не все модели поддерживают инструменты.

OpenAI, чтение живого графа:

```powershell
.\run.ps1 agent --provider openai --model MODEL_ID --mode live
```

Ключ берётся из `OPENAI_API_KEY`; если переменной нет, приложение предлагает скрытый ввод в обычном терминале. Затем выполняется отдельный вход IACPaaS. Ключи и пароль не нужно писать в чат или в исходный код.

Ollama, чтение живого графа:

```powershell
.\run.ps1 agent --provider ollama --model MODEL_ID --mode live
```

Без `--mode live` используется сохранённый корень. Для проверки HTTP-транспорта добавьте `--transport http`: приложение само запустит и остановит локальный MCP-сервер на свободном порту.

Чтобы Python и VS Code использовали **один уже работающий сервер**:

```powershell
.\run.ps1 agent --provider openai --model MODEL_ID --mcp-url http://127.0.0.1:8765/mcp
```

С Ollama замените `--provider openai` на `--provider ollama`. При `--mcp-url` режим данных и учётные данные определяются уже работающим сервером; локальный `--mode` не переключает его. Повторный вход IACPaaS не нужен.

По умолчанию запускается диалог. Пользователь отвечает на уточнения следующим сообщением, история сохраняется в памяти. `/exit` завершает работу. Для одного вопроса:

```powershell
.\run.ps1 agent --provider openai --model MODEL_ID --mode live --question 'Найди систему единиц физических величин и назови разделы непосредственно под корнем.'
```

В режиме одного вопроса ответ может оказаться уточняющим вопросом модели. Это нормальная остановка диалога, а не подтверждение выполнения исходной задачи; для продолжения используйте интерактивный режим.

## Архитектура

```text
VS Code custom agent ───────────┐
                               ├─ MCP stdio / Streamable HTTP
Python CLI → model tool calls ──┘      → server.py → domain.py
                                           → iacpaas_client.py → IACPaaS
```

- `agent.py` — CLI, вход, подключение к MCP и диалог.
- `agent_core.py` — ограниченный агентный цикл, проверка аргументов/результатов, политика и трасса.
- `providers.py` — адаптеры OpenAI Responses и Ollama. Решения о выборе инструментов принимает модель; в рабочем приложении нет списка заранее заданных вызовов.
- `agent_instructions.md` — правила и границы ответов Python-агента.
- `.github/agents/iacpaas.agent.md` — роль и список разрешённых инструментов агента IDE.
- `server.py`, `domain.py`, `iacpaas_client.py` — перенесённые без изменения сервер и доменный слой второго этапа.

Вместо LangChain/LangGraph реализован небольшой собственный runtime function calling: диалог → запрос модели → список вызовов → проверка схем/политики → MCP → результаты модели → ответ/следующий вызов/уточнение. Он покрывает соответствующий цикл задания, но не предоставляет визуальный редактор графов исполнения LangGraph.

## Ограничения и диагностика

Разрешены только `list_inforesources`, `get_inforesource`, `get_subgraph`, `count_graph`. Python-агент отбрасывает неизвестные инструменты, требует read-only-аннотации и не вызывает чтение по пути, который ещё не получен из каталога. Аргументы проверяются по JSON Schema, включая запрет лишних полей; ошибки возвращаются модели для исправления.

Пределы одного пользовательского запроса: 8 шагов модели, 16 вызовов инструментов, до 8000 символов вопроса. Контекст модели — до 1 МБ, ответ HTTP от модели — до 2 МБ, ожидание модели — до 180 секунд. При достижении лимита приложение сообщает об остановке, не выдавая её за успешный ответ.

Ограничения MCP остаются прежними: глубина 0..3, до 200 описаний вершин, графовая выдача до 128 КБ, HTTP IACPaaS до 2 МБ, таймаут 40 секунд. Каталог содержит один известный ресурс. Счётчики описывают только полученный фрагмент; полный подсчёт всех вершин графа и проверка онтологии не реализованы. Непустой `start` ещё не проверен на живом API.

Политика записи — запрет. Инструментов мутации нет ни у сервера, ни в allowlist Python, ни в custom agent IDE. Наличие запроса на изменение не означает, что изменение было выполнено.

Трассы Python сохраняются в `data/traces/agent-*.jsonl`: вопросы, имена/аргументы/результаты вызовов, конечные ответы и статус запуска. Заголовки, пароль, полный ответ авторизации и скрытые рассуждения модели туда не записываются; известные процессу секреты маскируются. Трасса может содержать данные графа и пользовательский текст. Папка исключена из архива и Git.

Для OpenAI `store=false`; история, включая возвращённые API элементы продолжения рассуждений, остаётся в памяти процесса и передаётся следующему запросу для корректного продолжения tool calling. Секрет модели не передаётся процессу MCP. Ответы графа считаются данными, а не инструкциями; ограничения инструментов дополнительно обеспечиваются кодом.

## Проверки и установка

После клонирования репозитория установите окружение и выполните проверки:

```powershell
.\setup.ps1
.\run.ps1 doctor
.\run.ps1 test
.\run.ps1 smoke
```

`doctor` проверяет наличие компонентов и локального Ollama, но не доступ аккаунта или способность конкретной модели вызывать инструменты. `test` выполняет 23 теста: 13 серверных и 10 агентных/провайдерных. В тестах используется явная подмена модели и HTTP-ответов провайдера. Тестовый сценарий через реальные stdio/HTTP проверяет поиск → чтение → неверную глубину → исправление → подсчёт. Тесты не подтверждают качество рассуждений LLM.

`smoke` проверяет MCP без модели, как на втором этапе. Живой MCP был проверен на втором этапе; это отдельное доказательство от запуска LLM. Доказательства и оставшиеся проверки перечислены в `verification.json` и `DEMO_SCENARIOS.md`.
