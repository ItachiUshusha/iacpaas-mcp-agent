# План показа перед следующим занятием

Главная цель: показать понимание выбранной онтологии и инфоресурса и один работающий сценарий прототипа. Это промежуточный результат, а не защита полностью завершённого агента.

## Подготовить заранее

1. Прочитать `01_Разбор_онтологии_и_базы.md`, особенно пример плотности и найденную неполноту.
2. Проговорить `02_Текст_выступления.md` один раз вслух.
3. Открыть в VS Code папку `корень репозитория`, README, `server.py`, `domain.py` и `data/materials-study/20261020T142201-73901c/mcp-materials-verification.json`.
4. Открыть браузер IACPaaS и войти в аккаунт. Учесть, что просмотрщик открывается нестабильно; не делать его единственным доказательством.
5. Сбор материалов успешно выполнен 21 октября. Для повторной демонстрации использовать подготовленный скрипт. Требуется один вход в терминале, пароль скрыт. Запись на платформе не выполняется.

```powershell
.\docs\class-prep\collect-materials.ps1
```

Скрипт читает корни и depth=3 для трёх ресурсов; исходные JSON и дерево `FACTS.md` сохраняются локально в `iacpaas-mcp-agent/data/materials-study/<запуск>/`. Подтверждённые экспортом коды добавляются в каталог. Если доступно окружение MCP, затем проверяются оба транспорта с тем же входом.

Критерий успешной проверки MCP материалов:

```text
OK: stdio, materials, 6 tool calls
OK: http, materials, 6 tool calls
Отчёт MCP: ...\mcp-materials-verification.json
```

Обе строки получены 21 октября. Сохранённый отчёт проверен: 12 успешных вызовов без ошибок. Основной показ — `04_Результат_живой_проверки.md` и сводку по ссылке и полный локальный отчёт. В `get_subgraph` показать пять классов, в `count_graph` — 6 вершин и 5 связей для depth=1. При повторном запуске оценивать его новый результат отдельно.

Если глубина 3 превышает ограничение размера, можно повторить сбор с `--depth 1`. Это даст меньший фрагмент, а не полный разбор. Автоматическое дерево FACTS.md не заменяет уже подготовленное объяснение структуры.

## Если интерфейс работает

В «Мой Фонд → Загрузки» выделить «База свойств материалов» и открыть просмотр. Если открылось окно «Просмотрщик инфоресурсов», раскрывать ветви **треугольником слева**. Нажатие на название может только выделить строку.

Показать:

```text
База свойств материалов
→ Физические свойства
→ Плотность вещества
→ Возможные значения / Числовой интервал
```

Затем единицы, синонимы и отсутствие значения верхней границы. Через значок перехода к метаинформации у корня открыть онтологию и раскрыть «Класс свойств». Назвать различие общего понятия «Свойство» и конкретного «Плотность вещества».

В меню «инфо» базы показать предупреждение о верхней границе температуры плавления. Не путать эту ошибку с отсутствием данных в плотности и не исправлять выданную базу.

## Дополнительный сценарий на системе единиц

Из корня репозитория:

```powershell
.\docs\class-prep\demo-current.ps1
```

Он выполняет живой сценарий на системе единиц через текущий код репозитория, выбирая доступное установленное окружение. Команда запросит вход в IACPaaS. После завершения открыть файл по напечатанному пути `Report`.

В JSON найти:

- `get_inforesource` → `source=live_api`, `requested_depth=0`.
- `count_graph` → для depth=0 одна вершина и ноль связей.
- `get_subgraph` → depth=1, три потомка; `node_occurrences=4`, `edge_occurrences=3`.
- Ошибочный путь `missing` → `RESOURCE_NOT_CONFIGURED`.
- `depth=99` → ожидаемая ошибка валидации.

Показать, что есть блоки stdio и http. Число вызовов — 7 на каждый транспорт, включая проверку ожидаемых ошибок.

## Если нет интернета или просмотрщик завис

1. Предметный разбор показать по `01_Разбор_онтологии_и_базы.md`: данные прочитаны из интерфейса 20–21 октября, это сохранённые наблюдения.
2. Для MCP открыть `04_Результат_живой_проверки.md` и сводку проверки материалов по ссылке: это сохранённый успешный живой запуск 21 октября, не текущий сетевой запрос.
3. Можно выполнить `demo-current.ps1 --mode snapshot`: он проверит MCP на сохранённом корне. В этом режиме нет потомков материалов, и он не подтверждает соединение с IACPaaS.
4. Открыть полученные при сборе локальные JSON и FACTS.md; не считать отсутствие узлов за глубиной 3 доказательством их отсутствия в полной базе.

Не представлять сценарий snapshot как live и не называть предопределённые вызовы smoke самостоятельной работой LLM.
