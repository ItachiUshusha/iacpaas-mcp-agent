## 3. Как устроена онтология

В просмотрщике раскрыта следующая структура. Стрелки в этом рисунке показывают структуру разбора; для ссылок отдельно указано, что они отображаются как переходы.

```text
Онтология базы свойств материалов
└── Класс свойств
    ├── Свойство
    │   ├── Возможные значения — АЛЬТЕРНАТИВА
    │   │   ├── → Числовой интервал
    │   │   ├── → Числовое значение — вещественный тип
    │   │   └── → Качественное значение
    │   ├── единица измерения — строковый тип
    │   ├── Синонимы
    │   │   └── синоним — строковый тип
    │   └── → Характеристика
    └── Класс свойств — вложенный класс
```

Что это означает для предметной области:

1. Свойства организуются в классы.
2. Классы могут содержать вложенные классы: структура не ограничена одним уровнем.
3. Свойство описывается не одним названием: у него предусмотрены возможные значения, единицы и синонимы.
4. Значения могут иметь разные формы: интервал, вещественные значения или качественные значения. Это не означает, что у каждого конкретного свойства должны быть заполнены все варианты сразу.
5. Переходы к «Характеристике» и типам значений показывают переиспользуемые элементы структуры. Точные целевые ресурсы этих переходов ещё не проверены; не называем их OWL-наследованием или конкретными внешними связями без проверки.

### Наблюдаемые ограничения отношений

| Элемент | Что показано в интерфейсе | Как объяснить |
| --- | --- | --- |
| Класс свойств под корнем | `set`, `all` | Отношение задаёт набор классов; ограничитель допускает разные способы формирования |
| Свойство внутри класса | `setmm`, `new-clone` | Набор может быть пустым; допускается новое понятие или клон |
| Возможные значения | `copy`, `new`; тип АЛЬТЕРНАТИВА | Для значений предусмотрена отдельная структурная ветка с вариантами |
| Единица измерения | `setmm`, `clone`; строковый сорт | Набор единиц может отсутствовать; значения представлены строками и создаются как клоны |
| Синонимы | `copymm`, `new` | Ветка синонимов может отсутствовать |
| Синоним внутри ветки | `set`, `new`; строковый сорт | Набор строковых синонимичных названий |

`specifier` описывает количество/организацию потомков, `restrictor` — допустимый способ их формирования. Для выступления достаточно объяснить различие и один пример `setmm + new-clone`. Полный онтологический валидатор в прототипе не реализован.

## 4. Как устроен инфоресурс с данными

Под корнем базы находятся пять классов. В интерфейсе каждый подписан `[Класс свойств]`:

1. Физические свойства.
2. Механические свойства.
3. Технологические свойства.
4. Эксплуатационные свойства.
5. Химические свойства.

Развёрнута ветка физических свойств. В ней наблюдались:

- Температура плавления.
- Температура кипения.
- Температура кристаллизации.
- Плотность вещества.
- Коэффициент теплопроводности.
- Удельная теплоемкость.
- Коэффициент термического расширения.
- Вложенный класс «Спектральные свойства» с коэффициентом отражения, коэффициентом поглощения и излучательной способностью.

Это список наблюдавшихся элементов ветки, а не обещание полного перечисления всех свойств базы.

## 5. Конкретный пример: плотность вещества

```text
База свойств материалов
└── Физические свойства [Класс свойств]
    └── Плотность вещества [Свойство]
        ├── Возможные значения
        │   └── Числовой интервал
        │       ├── Нижняя граница
        │       │   └── 0.0 [Числовое значение, вещественное]
        │       └── Верхняя граница
        │           └── потомки отсутствуют
        ├── кг/м³ [единица измерения, строковое]
        ├── г/см³ [единица измерения, строковое]
        └── Синонимы
            ├── Плотность [синоним, строковое]
            └── Плотность материала [синоним, строковое]
```

Главный вывод: здесь описано **свойство и допустимая форма его значений**, а не измеренная плотность конкретного материала. В этом примере нет марки сплава и его измеренного значения. Число `0.0` — нижняя граница показанного интервала.

Отсутствие потомков у верхней границы означает, что значение не задано в показанной ветке. Это не число 0 и не доказательство математической бесконечности.

### Сопоставление онтологии с данными

| Элемент онтологии | Конкретизация в базе |
| --- | --- |
| Класс свойств | Физические свойства |
| Свойство | Плотность вещества |
| Возможные значения / Числовой интервал | Интервал с нижней границей 0.0 и незаполненной верхней границей |
| Единица измерения, строка | кг/м³ и г/см³ |
| Синоним, строка | Плотность; Плотность материала |

Это пример того, что нужно объяснить по инженерии знаний: метауровень задаёт допустимую структуру, а информационный уровень наполняет её конкретными понятиями и значениями.

## 6. Обнаруженные особенности качества данных

В меню «инфо» база помечена как неполная. Указано конкретное место:

```text
База свойств материалов / Физические свойства /
Температура плавления / Возможные значения /
Числовой интервал / Верхняя граница
```

Для этой верхней границы отсутствует порождение по метаотношению к понятию «Числовое значение».

Также интерфейс сообщает, что метаинформации базы не сопоставлены онтологические соглашения. При этом выбранная онтология отдельно помечена как полная. Эти сообщения описывают разные проверки; они не означают, что у базы вообще нет связи с онтологией.

Как объяснить: «Мы обнаружили незаполненный обязательный элемент в данных и зафиксировали его, но не изменяли исходный ресурс». Не нужно дописывать границу или выдавать отсутствие за корректное неограниченное значение.

В комментариях физических свойств встречаются рабочие вопросы и предположения. Они сохранены как комментарии базы и не проверены нами как научные утверждения.
