# Каталоги и воспроизводимость

Операции работают с папками в «Моём Фонде» IACPaaS.

## Создание папок

После изменения кода перезапустите MCP-сервер и переподключите Cline:

    .\run.ps1 serve --transport http --mode live --login

На http://127.0.0.1:8765/mcp помимо чтения и поиска доступно создание папки:

    {"tool": "create_folder", "arguments": {"parent": "Загрузки", "name": "Демо команды", "description": "Учебный пример"}}

Примеры сообщений в Cline или нашем веб-чате:

- «Создай папку Демо команды внутри Загрузки в IACPaaS».

Пустой parent означает корень фонда. Промежуточные папки автоматически не создаются.
Snapshot отклоняет операции с кодом LIVE_REQUIRED.
Перед записью Python-агент в CLI и веб-чате сверяет действие и точный путь с прямой командой в текущем сообщении пользователя. Пример команды «Создай папку Загрузки/Демо». В Cline подтверждайте операции через интерфейс MCP. В конфигурации Cline список `autoApprove` пуст.

API создания: POST /api/storage-unit/folder/create, тело path/name/description.
Успех возвращается только при явном success=true без error/platformUnavailable.
Таймаут не означает, что сервер не выполнил изменение. Клиент не делает повторных HTTP-запросов;
наш агент блокирует повтор одинаковой операции записи в том же диалоге.
После ошибки проверьте папку в фонде вручную. Другие MCP-клиенты управляют повторными вызовами самостоятельно.

Создание папки не меняет catalog.json. Полное перечисление папок фонда пока не реализовано.
## Перемещение папки в корзину

Запустите HTTP MCP с веб-входом в «Мой Фонд»:

    .\run.ps1 serve --transport http --mode live --login --fund-login

Пароль вводится один раз в терминале. После входа веб-чат и Cline используют этот MCP-сервер.
Проверочный запрос: «Перемести тестовую папку Загрузки/MCP-demo-1111 в корзину IACPaaS».
В журнале инструмента проверьте `ok=true` и `operation=moved_to_trash`, а в фонде проверьте корзину.

Инструмент `delete_folder` проверяет тип и точный путь объекта, затем вызывает
операцию `/fund/deleteItem` с `recycle=true`, как кнопка удаления в интерфейсе платформы.
Маршрут принадлежит веб-интерфейсу и может меняться вместе с ним. Для него нужна веб-сессия.
Отдельный публичный режим `trashIR` применяется к инфоресурсам.

## Проверка на вашей учётной записи

    .\run.ps1 folders --create-only --transport http

Скрипт спросит пароль скрыто и создаст одну папку MCP-demo-UUID в «Загрузках».
Можно выбрать `--transport stdio` или `--transport http`. Для перемещения созданной папки в корзину используйте указанный выше HTTP-сервер с веб-входом.
Старые команды `folders` и `folders --resume-report …` остановятся до входа и записи.
Отчёт сохраняется в локальную data/folders-demo/, не включается в Git.

При отказе API клиент сохраняет ограниченную диагностику в data/folder-api-errors/.
В неё не включаются заголовки запроса; известные токены маскируются.
В сообщение инструмента попадает имя файла, но не полный ответ платформы.
Скрипт выводит короткую ошибку вместо вложенного ExceptionGroup traceback.

## Воспроизводимый режим модели

Сортировка выдачи каталога и определений инструментов включена всегда.
JSON в модель и текстовый ответ MCP сериализуются со стабильным порядком ключей.
Порядок потомков графа сохраняется: его сортировка могла бы изменить смысл упорядоченных отношений.

Для Ollama с уже установленной моделью, поддерживающей инструменты:

    .\run.ps1 web --provider ollama --model MODEL_ID --mode live --deterministic --seed 42

MODEL_ID замените точным именем своей модели. Для фиксированного compatible API:

    .\run.ps1 web --provider compatible --base-url https://YOUR-ENDPOINT/v1 --model MODEL_ID --mode live --ask-key --deterministic --seed 42

Для OpenRouter дополнительно закрепляется провайдер:

    .\run.ps1 web --provider compatible --model MODEL_ID --model-provider PROVIDER_SLUG --mode live --ask-key --deterministic --seed 42

MODEL_ID и PROVIDER_SLUG берутся из доступных моделей и их провайдеров в вашем аккаунте.
У OpenRouter сохраняется ограничение нулевой цены; платный fallback не включается.
В режиме --deterministic запрещены openrouter/free и openrouter/auto:
они автоматически выбирают модель. Провайдер фиксируется через only и allow_fallbacks=false.
Если выбранный провайдер не поддерживает seed/temperature/tools, запрос может быть отклонён;
код не убирает настройки незаметно. CLI agent принимает те же параметры.

При первом обращении к Ollama или compatible API агент передаёт `temperature=0` и фиксированный `seed` (по умолчанию 42). В адаптере OpenAI Responses режим работает через воспроизведение шагов без параметра `seed`. Агент исполняет MCP-вызовы последовательно.

При каждом шаге агент вычисляет SHA-256 от истории диалога и схем доступных инструментов. В историю входят системные инструкции, вопрос, предыдущие шаги модели и результаты MCP. При совпадении входа агент воспроизводит сохранённый выбор инструмента и его аргументы или сохранённый текст. Все запланированные MCP-вызовы выполняются заново. Изменившийся результат чтения меняет вход следующего шага, поэтому модель заново строит вывод по этим данным. Проверка ссылок использует результаты текущих вызовов.

При немедленном повторе того же вопроса о чтении агент восстанавливает контекст перед предыдущим ответом. В новом диалоге с теми же входами используется общий кэш запущенного веб-чата. Команды создания и удаления папок идут через обычные проверки MCP. Шаги, которые запрашивают изменение, не кэшируются.

Кэш хранится в оперативной памяти одного запуска и вмещает до 128 модельных шагов размером до 256 КиБ каждый. После перезапуска, вытеснения записи или при изменении контекста соответствующий шаг генерируется заново. Фиксированные параметры снижают вариативность первого обращения к провайдеру. Точное совпадение текста обеспечивается воспроизведением сохранённых шагов при совпадении входа.

В журнале веб-чата показано, сколько шагов модели воспроизведено. Вызовы MCP отображаются отдельно. Настройки действуют на Python-агент и веб-чат.
Cline использует собственную модель: temperature/seed и фиксированную модель надо настраивать в самом Cline,
если его провайдер это позволяет. MCP-сервер управляет стабильностью данных, а не генерацией Cline.

## Где реализовано

- server.py — MCP-методы и аннотации чтения/изменения.
- domain.py — правила путей, защищённые ресурсы, стабильная сортировка каталога.
- iacpaas_client.py — запросы создания и переноса в корзину, локальная диагностика отказов.
- generation.py, providers.py — параметры генерации и воспроизведение модельных шагов.
- agent_core.py — порядок инструментов, контекст повтора, проверка схем и защита от повторной записи.
- folders_demo.py — живой сценарий проверки на временных папках.
