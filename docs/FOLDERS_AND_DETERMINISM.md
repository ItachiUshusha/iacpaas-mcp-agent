# Каталоги и воспроизводимость

Обновление 28 октября 2026. Каталог IACPaaS здесь означает папку в «Моём Фонде».
Это не локальный файл catalog.json и не вершина графа.

## Создание и удаление папок

После изменения кода перезапустите MCP-сервер и переподключите Cline:

    .\run.ps1 serve --transport http --mode live --login

На http://127.0.0.1:8765/mcp помимо инструментов чтения и поиска доступны два метода работы с папками:

    {"tool": "create_folder", "arguments": {"parent": "Загрузки", "name": "Демо команды", "description": "Учебный пример"}}
    {"tool": "delete_folder", "arguments": {"path": "Загрузки/Демо команды", "confirm_path": "Загрузки/Демо команды"}}

Примеры сообщений в Cline или нашем веб-чате:

- «Создай папку Демо команды внутри Загрузки в IACPaaS».
- «Перемести папку Загрузки/Демо команды вместе с содержимым в корзину IACPaaS».

Пустой parent означает корень фонда. Промежуточные папки автоматически не создаются.
Snapshot отклоняет операции с кодом LIVE_REQUIRED.
Удаление выполняется только через корзину (trashIR). Корзина, Загрузки, ресурсы из catalog.json
и их родительские папки защищены от удаления. Для остальных путей требуется точно указать папку.
confirm_path защищает от расхождения аргументов, но не является независимым доказательством согласия человека:
клиент MCP отвечает за разрешение операции (в конфигурации Cline autoApprove остаётся пустым).

API создания: POST /api/storage-unit/folder/create, тело path/name/description.
Удаление: DELETE /api/data/delete, тело path/mode=trashIR.
Успех возвращается только при явном success=true без error/platformUnavailable.
Таймаут не означает, что сервер не выполнил изменение. Клиент не делает повторных HTTP-запросов;
наш агент блокирует повтор одинаковой операции записи в том же диалоге.
После ошибки проверьте папку и корзину вручную. Другие MCP-клиенты управляют повторными вызовами самостоятельно.

Создание папки не меняет catalog.json. Полное перечисление папок фонда пока не реализовано.
Публичная спецификация не предоставляет отдельного метода проверки типа папки перед удалением:
delete_folder передаёт указанный путь общему механизму удаления единиц хранения.
Поэтому нельзя использовать его для неизвестного пути или считать локальный каталог списком папок.

## Проверка на вашей учётной записи

    .\run.ps1 folders

Скрипт спросит пароль скрыто, создаст по одной папке MCP-demo-UUID в Загрузках через stdio и HTTP
и переместит каждую в корзину только после подтверждения успешного создания.
Существующие папки он не выбирает для удаления. Если создание не подтвердилось, удаление не выполняется.
Отчёт сохраняется в локальную data/folders-demo/, не включается в Git.

**Статус:** контракты, схемы, ограничения и оба MCP-транспорта проверены локальными тестами; всего прошли 44 теста.
Авторизованный прогон создания/удаления на IACPaaS пока не выполнен.
Применимость общего режима trashIR именно к папкам требует этого живого прогона;
успешные тесты с подменённым API этого не доказывают.

## Воспроизводимый режим модели

Сортировка выдачи каталога и определений инструментов включена всегда.
JSON в модель и текстовый ответ MCP сериализуются со стабильным порядком ключей.
Порядок потомков графа сохраняется: его сортировка могла бы изменить смысл упорядоченных отношений.

Для Ollama с уже установленной моделью, поддерживающей инструменты:

    .\run.ps1 web --provider ollama --model MODEL_ID --mode live --deterministic --seed 42

MODEL_ID замените точным именем своей модели. Для фиксированного compatible API:

    .\run.ps1 web --provider compatible --base-url https://YOUR-ENDPOINT/v1 --model MODEL_ID --mode live --ask-key --deterministic --seed 42

Для OpenRouter дополнительно закрепляется провайдер:

    .\run.ps1 web --provider compatible --model MODEL_ID --model-provider PROVIDER_SLUG --mode live --ask-key --deterministic --seed 42

MODEL_ID и PROVIDER_SLUG берутся из доступных моделей и их провайдеров в вашем аккаунте.
У OpenRouter сохраняется ограничение нулевой цены; платный fallback не включается.
В режиме --deterministic запрещены openrouter/free и openrouter/auto:
они автоматически выбирают модель. Провайдер фиксируется через only и allow_fallbacks=false.
Если выбранный провайдер не поддерживает seed/temperature/tools, запрос может быть отклонён;
код не убирает настройки незаметно. CLI agent принимает те же параметры.

Режим передаёт temperature=0, seed=42 (или указанный seed).
Совместимый API также получает parallel_tool_calls=false; вызовы агент исполняет последовательно.
В OpenAI Responses этот режим явно отклоняется, потому что у адаптера нет общего контракта seed.
Без --deterministic сохраняются прежние настройки генерации.

Для сравнения используйте новый диалог с одним и тем же вопросом, той же моделью, провайдером,
seed, инструкциями и одинаковыми исходными данными. «Повтори» в старом чате — уже другой контекст.
При обновлении модели, инфраструктуры или живой базы текст может отличаться.
**Это повышение воспроизводимости, а не гарантия побайтово одинакового ответа LLM.**
Кэш ответов не используется: живые данные перечитываются.

Параметры видны в /api/status, интерфейсе веба и локальной трассе.
Настройки generation.py действуют на наш Python-агент и веб-чат.
Cline использует собственную модель: temperature/seed и фиксированную модель надо настраивать в самом Cline,
если его провайдер это позволяет. MCP-сервер управляет стабильностью данных, а не генерацией Cline.

## Где реализовано

- server.py — MCP-методы и аннотации чтения/изменения.
- domain.py — правила путей, защищённые ресурсы, стабильная сортировка каталога.
- iacpaas_client.py — HTTP-запросы создания и удаления.
- generation.py, providers.py — параметры воспроизводимости и маршрутизация модели.
- agent_core.py — порядок инструментов, проверка схем, блокировка повторной записи.
- folders_demo.py — живой сценарий проверки на временных папках.
