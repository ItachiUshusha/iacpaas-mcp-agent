# Ответы с проверяемыми источниками

Газовые составы читаются из ресурса `Загрузки/База технологических газов`. В режиме `live_api` данные запрашиваются у IACPaaS на глубине 10. Снимок `saved_snapshot` содержит корень системы единиц для проверок без входа.

## Что добавлено

- search_inforesource: поиск внутри universal-экспорта по name/value/meta/link/comment.
  Запрос — одно слово или основа: водород, аргон, примес.
  Результат содержит путь по дереву, поля узла, первые 20 потомков, JSON Pointer,
  evidence_id и хеш экспорта.
- compare_node_children: пересечение меток непосредственных потомков двух выбранных узлов.
  Результат содержит исходные записи с обеих сторон каждого совпадения.
- read_export_node: чтение найденного узла и ограниченного числа его потомков по
  pointer и export_sha256 из поиска или анализа составов. depth должен совпадать
  с requested_depth того результата. Перед чтением экспорт получается заново;
  изменившийся хеш даёт EXPORT_CHANGED. levels ограничивает глубину потомков,
  max_nodes — их число вместе с выбранной вершиной. Ссылки не разворачиваются.
- analyze_gas_composition читает вложенные «Объёмные доли компонентов» в газовой базе, сохраняет единицы и операторы пределов. Ранжирование использует нижнюю границу доли основного газа. Сравнение берёт компоненты с верхним пределом, встречающиеся хотя бы в одной марке каждого класса.
- Статус цитирования в веб-чате: ссылки подтверждены, отсутствуют или требуют повторного чтения источника из истории.
  Проверяются также все ссылки в группах вида `[E1, E2]`; в интерфейсе каждая открывает свою запись.
  Нажатие на [E...] раскрывает ресурс, путь, источник, глубину и исходные поля.
- Статистика переименована в «Прочитанный фрагмент» и отделена от обоснования ответа.

Проверяется существование ссылки в успешном результате инструмента.
Это **не независимая семантическая проверка всего текста LLM**:
реальную запись тоже можно неверно истолковать.
Число прочитанных вершин не доказывает предметный вывод.
В Cline доступны те же MCP-данные и evidence_id, но веб-проверка цитирования там не выполняется.

Для каждого нового вопроса о составах требуется свежее чтение. Если его SHA-256,
ресурс, источник и глубина совпадают с экспортом из истории, ранее полученные
ссылки на этот экспорт подтверждаются заново. Одной истории без нового чтения
недостаточно. Изменившийся хеш не подтверждает старые ссылки; модель получает
одну попытку исправить ответ или перечитать нужные записи. Предупреждение
сохраняется, если исправление не удалось. Интерфейс отдельно показывает ссылки
из истории и ссылки, которых нет среди полученных данных.

Успешное чтение подходящего ресурса не требует дополнительного общего поиска
по фонду. При нехватке данных и при завершении по лимиту агент повторяет исходный
вопрос в служебной подсказке, чтобы не подменять предметную задачу отчётом о поиске.

После обнаружения ресурсов схемы инструментов чтения перечисляют полные допустимые
пути. Если модель всё же передала только название, агент сопоставляет его с точным
названием или последней частью пути уже обнаруженных ресурсов. Единственное
совпадение заменяется подтверждённым полным путём и фиксируется в трассе как
resource_path_resolved. Несколько совпадений дают PATH_AMBIGUOUS; ненайденное имя
требует поиска в каталоге или фонде. Префиксы папок не угадываются, операции записи
не используют такое разрешение названий. При воспроизведении вопроса каталог
обнаруженных ресурсов восстанавливается вместе с контекстом.

## Ограничения

Поиск: depth=0..10, ответ API до 2 МБ, обход до 20000 узлов, выдача до 30 совпадений и 128 КБ.
Старые методы сохраняют depth=0..3 и max_nodes=200.
JSON Pointer относится к экспорту и не является параметром start API.
Для JSON Pointer в start агент и MCP возвращают INVALID_START_PATH до обращения
к платформе. Указатель не преобразуется в путь вершины автоматически.
Цепочка названий без окончания ';' также отклоняется. В Python-агенте схемы
get_subgraph/count_graph допускают только пустой start; для конкретных записей
предлагается read_export_node. Ручные MCP-клиенты могут использовать подтверждённый
платформенный путь, но не должны собирать его из поля trail.
При изменении экспорта сравнение отклоняется с EXPORT_CHANGED.
Ссылки не разворачиваются; пустой/нераскрытый список даёт INSUFFICIENT_DATA.
Синонимы и формулы автоматически не объединяются.
Отсутствие совпадений в ограниченном экспорте не доказывает отсутствия сведений во всём фонде.

Идентификатор `[E…]` позволяет открыть путь в источнике и исходные поля. В публичном репозитории сохранены документация и обезличенные сводки. Выгрузки учебных ресурсов и исходные диалоги хранятся в локальной `data/`.

## Запуск

Перезапустите MCP и веб-чат, обновите страницу Ctrl+F5 и начните новый диалог.
Работающие процессы продолжают использовать старый код.

    .\run.ps1 serve --transport http --mode live --login

В другом терминале используйте прежнюю команду web с выбранной моделью и
--mcp-url http://127.0.0.1:8765/mcp.

Проверочный запрос для доступных баз:
«Найди внутри подключённых ресурсов записи водорода и аргона. Покажи исходные поля
и ссылки на записи. Не считай химический элемент списком примесей газа».

Проверка газовой базы при наличии доступа к ресурсу:
«Какие общие примеси указаны у газов на основе водорода и аргона? Покажи исходные записи с обеих сторон».

Для проверки и подключения нового ресурса укажите его точный относительный путь
из «Моего Фонда». Например, если база находится в «Загрузках»:

    .\run.ps1 study --resource-path 'Загрузки/База технологических газов' --depth 10

Команда сохраняет экспорт в локальной папке `data/` и добавляет в каталог только
ресурс с подтверждёнными названием и кодом. После подключения перезапустите MCP.

Автоматические тесты покрывают оба транспорта MCP, поиск, изменение экспорта, пересечение и проверку ссылок. Для контролируемых сценариев используются синтетические графы. Живой прогон веб-чата проверяется отдельно.
